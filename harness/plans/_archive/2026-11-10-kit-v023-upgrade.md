## 目标与非目标

- 目标：把 Android 仓的 harness 从 kit v0.2.2 升到 v0.2.3——宿主传感器上游化（删掉宿主 fork）、`check_plan` 无扩展名根文件修复、`harness-selftest` 可用、`static-gates` 证据 claim；用真实仓验证 kit 一直标注“未验证”的升级路径。
- 非目标：不改 app 代码/单测；不升级 kit 本身（v0.2.3 已在 iOS 源仓发布）；不引入 `check_docmap`/`statusPolicy` 等 v0.3.0 能力；产品 Next（延迟/流式/增量翻译）不在本轮。

## 升级流程实测（kit 0.2.2 → 0.2.3）

1. **dry-run 对比**：`harness-init --dry-run` 对已接入仓只报 27 个 CONFLICT + 1 个 `RENDER Makefile.harness`——kit 没有 in-place 升级命令，且直接 `--force` 会覆盖项目文档，不可用。
2. **版本渲染 diff**：临时目录用 v0.2.3 渲染 standard/android，与本仓逐文件比对，真实差异 = `tools/check_agents.py`、`tools/check_plan.py`、`tools/check_hygiene.py`、`tools/check_layers.py`、`Makefile`（kit 目标段）、`harness/config.json`（kitVersion/配置）；`.github/workflows/verify.yml`、`.githooks/pre-push`、其余 tools 逐字节相同；项目自有文档不回写。
3. **负向注入先发现回归**：先用 v0.2.3 的 `harness-selftest` 打升级前 HEAD，M5（指令文件本机路径）与 M8（跟踪文件本机卷路径）注入未被拒绝——原因是历史清洗把配置里的 `/Users/`、`/Volumes/` 替换成了 `/local/`，门禁从此只匹配占位符。升级中恢复真实模式后两项转 PASS。
4. **schema 迁移**：`layers` 由宿主私有键（domainForbidden/servicesForbidden/featuresForbiddenImports/featuresServicesAllowlist/engineClasses/engineAllowedPaths）映射为通用 `rules`（pathPrefix + forbiddenImports + allowedImports）+ `symbolGuards`；规则语义保持 R1–R3/R4/R5 等价。
5. **收尾**：clean tree 跑 `make verify-static` + kit `harness-selftest`，生成 `static-gates` 证据，计划 done 后归档。
